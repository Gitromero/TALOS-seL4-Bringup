# Notes for AI coding assistants (and humans skimming)

PolarFire SoC Discovery Kit (MPFS-DISCO-KIT) seL4 bring-up. Shared by the team: keep everything host-neutral.

- **Current state:** `history/bringup-log.md`. Its dated updates at the end are the current state; the latest one wins. Add a new dated update there when you verify or change something important, and say plainly what ran on the real board and what didn't.
- **Board commands:** `scripts/board.py status | ports | flash [--lan] [image] | console [--hss|--uart3] | send TEXT | reset | tftp | install-udev` (`--help` on each). `flash` loads over USB (YMODEM via U-Boot `loady`), `flash --lan` over TFTP. Guides: `docs/flashing.md` (loading, shared consoles), `docs/getting-started.md` (host and serial setup), `docs/sd-card.md` (SD install and Linux restore). How the tools are built and their conventions: `docs/tooling.md`.
- **Serial ports:** never hard-code `ttyUSB` numbers. Use `/dev/polarfire-*` (udev rule) or `/dev/serial/by-id/*FlashPro5*-ifNN-port0`: if01 HSS, if02 U-Boot/seL4, if03 third UART, if00 JTAG. Only one program can read a port at a time unless it goes through the serial-share broker: always use it (`scripts/board.py console`, `scripts/board.py send`, or `polarfire.serial_share.ensure_broker()` from Python) and never open the device directly. Don't start a plain picocom/screen on a port a tool needs.
- **Safe by default:** `board.py flash` (USB or `--lan`) is RAM only. Never `saveenv` in U-Boot. Never write the SD card except through `scripts/install-to-boot.sh` (dry run by default, keeps `boot-linux.scr`). Never touch the FPGA/HSS, and never use the HSS `YMODEM` command (it writes eMMC/QSPI).
- **Board state:** `board.py reset` and `board.py flash` reboot the board; whatever runs on it is lost. Check `board.py status` first if the board might be in use by someone else.
- **Tests:** `tests/run.sh` runs every offline check (no board needed) and must pass before committing. Hardware behavior is verified only by a real `board.py flash`; say so when you haven't run one.
- **Privacy rule for committed files:** no usernames, home paths, host names, real IP/MAC addresses or board serial numbers. Use examples like `192.168.1.10`. Refer to the main TALOS repository only as "the main TALOS repository", never by name. `scripts/privacy_audit.py` scans binary artifacts; `tests/test_repository.py` checks text files.
- **Images:** `images/sel4test.uImage` is the only hardware-verified image (SHA-256 in `images/SHA256SUMS`). Rebuilds go through `scripts/build-sel4test.sh` and must stay byte-identical.
- **Layout:** active tools in `scripts/`, tests in `tests/`, guides in `docs/`, experiments in `experiments/`, dated records in `history/` and `reports/` (records keep the tool names of their time).
- **Style:** see `docs/tooling.md#conventions`. Bash scripts use `set -euo pipefail` and a usage header that `--help` prints; Python tools use argparse and the standard library only; inline Python runs with `python3 -I`. Docs are plain, direct Markdown with tables, and record verification dates.
